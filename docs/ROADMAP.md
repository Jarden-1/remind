# Remind 后续开发计划

日期：2026-10-15（北京时间）。规划基线：`v0.1.4` / `1ce81c7`。P0 的代码修复和事件规范现已进入 v0.1.5 审核，具体结果见 [修复记录](FIXES-0.1.5.md)。系统登录、长时间资源和完整跨版本安装验收仍未冒充完成；会议识别和桌宠玩法继续作为后续需求。

## 1. 当前基线

本次已将本地 `main` 从 `8537664` 快进到 `1ce81c7`，没有合并冲突。安装锁定依赖后，本地验证通过：后台与发布脚本 49 项测试、前端 18 项测试，共 67 项；类型检查、独立前端构建和桌面生产构建通过。本次未启动桌面应用或预览服务，未改变本机登录项。

GitHub 已公开发布 v0.1.0 至 v0.1.4。v0.1.4 的 Mac、Windows 构建和草稿发布流程成功；发布页已有两种 Mac 架构的 DMG／ZIP、Windows x64 安装器及更新元数据。构建成功不等于安装、系统登录和跨版本升级已经通过真机验收。

本次新增改动已纳入基线：

- 菜单栏倒计时；Windows 托盘提示同步状态。
- 看板内直接修改时长、重置计时、定时暂停、快捷键。
- 休息时延后 5 分钟或跳过本次。
- 默认开启自启动，保留用户后续选择；处理 Mac 登录项批准、安装位置和后台启动。
- 启动后及定期检查更新，下载／安装仍由用户决定；Mac 无 Developer ID 时打开发布页。
- Mac ad-hoc 签名、安装包签名检查、双平台产物齐全后生成 Release 草稿。
- 原生标题栏最小化／退出及拖拽区域点击修正。

继续保持：本地桌面后台与 React 界面分离，不增加云服务器、账号或统计看板。暂不开始桌宠玩法。

## 2. 推荐开发顺序

| 阶段 | 建议版本 | 重点 | 完成条件 |
| --- | --- | --- | --- |
| P0 | v0.1.5 | 稳定现有操作、安装升级和系统行为 | 新安装与旧版升级验收有记录；关键组合场景通过；PR 自动检查生效 |

## 3. P0：先把 v0.1.4 变成可靠基线

### 3.1 同步规格和验证记录

- SPEC 默认设置仍写“开机启动关闭”，当前代码和 README 已改为默认开启。以当前版本为基线同步说明，不在本轮擅自反转用户的新决定。
- DESKTOP 仍写“尚无 Release”，并记录 59 项测试；实际已有公开 v0.1.4，本次跑通 67 项。更新记录时区分自动测试、构建结果和真机验收。
- 补齐定时暂停、重置、延后、快捷键的正式行为定义和组合验收，避免预览服务与桌面服务逐步分叉。

### 3.2 处理已有功能的失败边界

- 自启动注册目前位于启动初始化链上；系统调用抛错会进入整体启动失败路径。应隔离登录项失败：应用仍可使用，设置显示失败并允许重试。旧设置迁移和用户明确关闭自启动必须保持有效。
- 优先覆盖“定时暂停 + 休眠／重启”“手动暂停后主动休息 + 延后”“跨工作时段 + 延后”“自动检查更新 + 手动检查”的组合。先确定期望行为，再加回归测试。
- 对最小化、退出、标题栏点击、数字编辑、菜单、快捷键增加少量真实界面冒烟验证。现有纯函数测试不能证明原生窗口实际收起或键盘焦点正确。
- 外接屏缩放、负坐标、热插拔、全屏应用所在空间、锁屏后休眠再解锁，按真实安装包验收。Windows 和 Intel Mac 的真机状态应单独记录，不能用 CI 构建代替。

### 3.3 补上安装和升级闭环

- 从公开 v0.1.4 升级到下一个测试版本，检查设置、自启动选择和手动暂停意图保留，退出后没有旧进程；登录时不弹看板。
- Windows 验证用户主动下载／安装，以及断网、下载中断和安装失败后的恢复。
- Mac ad-hoc 包验证手动下载覆盖安装；具备 Developer ID 与公证后，再验收应用内安装。不要把 ad-hoc 包的可运行等同于完整系统信任或原生更新验收。
- 做一次连续运行及资源测量，记录后台 CPU、内存、窗口反复创建后的变化。先取得基线，再按问题优化，不预先承诺没有测量依据的资源指标。

### 3.4 保证以后改动不会轻易回退

现有 workflow 只在手动运行或版本标签推送时执行。补充 PR 和 main 的测试／类型／构建检查；安装包仍按现有发布流程生成，保留双平台都成功才发布草稿的约束。证书始终留在受保护配置，不进入源码或安装包。

**P0 验收交付：** 一份结果明确的系统／场景验收表、关键失败路径的回归测试、CI 检查和更新后的规格。没有真机条件的项目标记未验收。

## 4. P1：会议识别分两步，先验证再接入

### 4.1 技术探针

先在日常使用的 Mac 上验证腾讯会议和飞书会议，再扩展 Windows。记录操作系统、客户端版本、所需权限及可用信号；不先假设四种组合都能可靠支持。

最少场景：软件仅后台运行、飞书聊天、语音消息、真实入会、静音、关摄像头、最小化、共享屏幕、退出会议但不退出软件，以及权限被拒绝／运行中撤销。

不把“存在进程”或“麦克风被使用”单独当成开会。探针只读取识别所需的本地状态，不录音、不截屏、不读取会议内容或参会人；日志也不保存会议标题。探针未证明可靠前，产品仍显示“待接入”，手动暂停照常可用。

**探针出口：** 按“系统 × 软件 × 已测版本”给出支持、不可用或仍不确定的结论，以及实测误判和所需权限。根据结果审核可支持范围，再决定正式实现。

### 4.2 正式接入

- 检测器只报告每个软件的状态，计时核心决定暂停／恢复。协议区分“开会、未开会、未知、不支持”，不能把检测失败当作没有会议。
- 增加会议会话集合和状态说明。目前 `meeting` 只有暂停原因占位，主进程尚无真实检测入口；面板会议文案还固定写腾讯会议，应改为读取实际软件名称。
- 同时开两款会议软件时，只有全部已确认会议结束才解除会议原因；手动暂停和工作时段继续独立生效。
- 开始／结束信号做稳定确认，具体时间根据探针实测决定。会议开始收起提前提示和休息窗口；会议结束后在允许工作且没有其他暂停原因时重新计满间隔。
- 权限不足和检测异常按 SPEC 的降级规则处理，并有用户手动控制入口；不会在检测失效时突然认定会议结束并弹全屏。
- 先提供明确标记的实验版本，稳定版不自动收到实验更新。发布流程需要明确标注预发布，不依靠版本名字让用户自行判断。

**P1 验收交付：** 支持矩阵、误判记录、权限流程，以及会议与手动暂停／锁屏／时段／多屏的组合结果。仅对通过验证的组合声明支持。

## 5. P2：正式分发和小范围体验完善

- 按分发范围配置 Mac Developer ID 与公证、Windows 签名，重新完成安装与升级验收。Mac 应用内升级依赖这一步，当前手动下载路径继续保留。
- 统一设置中的版本信息、更新说明、开源声明与许可证；对外许可证由维护者决定。
- 根据真实问题优化退出后的工作窗口焦点恢复、小屏／系统字体缩放及键盘操作；不再为了增加功能堆放按钮或说明。
- 有国内下载失败的实际数据后，再考虑 HTTPS 镜像。保持更新动作由用户决定，避免现在搭建没有需求依据的下载后台。

## 6. P3：为桌宠留扩展点，不提前做玩法

保留当前主进程计时核心。按需要逐步拆出窗口协调、托盘、自启动和会议适配，避免把新增逻辑全部塞进 main/index.ts；不做整套架构重写。

v0.1.5 已增加 v2 计划／实际时长字段，区分延后结果，并保留 v1 记录兼容、备份和事件去重。接入养成前继续需要：

- 明确计划时长、实际展示时长及 completed／skipped／snoozed／interrupted／display_failed；为新字段制定事件版本和旧记录读取策略。
- 处理只有准备阶段、窗口未成功展示、异常退出和重复事件的情况；完整休息不得重复结算。
- 桌宠通过只读快照和已确认事件感知计时，不能自己控制后台时钟；宠物动画崩溃不能影响提醒。
- 奖励、数值、离线成长、素材和交互方式另写玩法规格，确认后开发。现阶段不增加统计页或云端存储。

## 7. 提交审核的产品建议

这些是建议，不在本次直接实现：

1. **会议识别默认关闭，按已验证组合开放。** 需要系统权限的步骤在实际开启时说明；检测不可用始终保留手动控制。
2. **第一版延后继续固定为 5 分钟。** 暂不加多种延后档位或强制次数限制，先观察使用反馈；是否保留此前手动暂停意图需写入明确规则。
3. **投屏、演示和游戏免打扰另列需求。** 不把全屏应用一概视为会议，避免用户看视频或玩游戏时永远收不到久坐提醒。
4. **完成核心验收后再开始桌宠。** 先补事件和兼容规则，玩法不与会议识别同时扩张。

建议下一轮先执行 P0，同时完成会议探针方案；探针结果和本节产品规则审核后，再进入正式会议功能。
