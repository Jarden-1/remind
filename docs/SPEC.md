# Remind 产品规格

版本：0.3 草案 · 日期：2026-10-12（北京时间）

状态：基础桌面后台及用户主动更新流程已实现，当前交付与验证边界见 [桌面后台说明](DESKTOP.md)。会议识别、开机启动、正式签名发布及完整跨平台验收尚未完成；待审核建议仍保留。

## 1. 文档约定

- **已确认**：用户明确提出或认可的方向。
- **建议**：为形成可实现、可测试的方案提出的默认行为，尚非用户最终决定。
- **待验证**：依赖系统、第三方客户端或实际测量，不能仅凭设计保证。

本文中的建议是连贯的第一版基线，审核时可以按决策编号修改。没有单独确认过的数值、操作和范围均按“建议”理解。

关联文档：[技术设计](TECHNICAL_DESIGN.md)、[开源调研](OPEN_SOURCE_RESEARCH.md)。

## 2. 产品目标与已确认需求

核心目的：提醒办公用户不要连续久坐，按自己设定的间隔起来活动。

| 编号 | 已确认需求 |
| --- | --- |
| C01 | 支持 Windows 和 macOS 电脑下载安装，不做安卓手机或 iPhone |
| C02 | 核心场景为每隔 45 分钟起来活动，用户可以自定义提醒间隔 |
| C03 | 到时间全屏显示“休息” |
| C04 | 默认无铃声，允许用户开启铃声 |
| C05 | 可以手动暂停，用户在会议等场景自行控制 |
| C06 | 希望自动识别会议并暂停提醒，且提示用户；优先腾讯会议、飞书会议 |
| C07 | 会议暂停是临时的，会议结束后自动恢复；不能只因软件运行就一直暂停 |
| C08 | 日常只需小看板，不需要大型主页面 |
| C09 | 未来可能加入桌宠、养成；当前先完成基础功能，架构考虑扩展 |
| C10 | 优先参考和复用开源项目；补充用户未考虑的产品建议，交由用户审核 |
| C11 | 休息时长默认 3 分钟，并支持用户自定义 |
| C12 | 休息前提前 1 分钟进行轻提醒，不采用提前 10 秒的方案 |
| C13 | 第一版支持设置工作时段，在指定时间范围内自动提醒 |
| C14 | 提供软件更新系统，由用户自主决定是否下载及何时安装 |

45 分钟是产品默认值，不作为医疗建议。程序不能判断真实坐姿或确认用户确实离开座位。

## 3. 第一版范围建议

### 3.1 基础闭环

- 安装、启动、单实例运行、退出。
- 托盘／菜单栏小看板，查看剩余时间及暂停原因。
- 设置提醒间隔和休息时长。
- 休息前 1 分钟轻提醒。
- 设置工作日与每日工作时段，时段外自动停止周期提醒。
- 静音全屏休息、可选开始铃声。
- 手动暂停／恢复、现在休息、提前结束休息。
- 锁屏与休眠处理、本地保存设置。
- 多显示器休息覆盖与退出控制。
- 可选开机启动。
- 用户主动检查、下载及重启安装更新。

### 3.2 同一轮产品目标中的会议能力

先验证腾讯会议和飞书在 Windows、macOS 下的客户端行为，按“系统 × 软件 × 已测版本”开放支持。

基础闭环可以先形成内部测试包，但会议能力未通过验证前，不能把整个产品标为已完成所有已确认需求。某个平台暂不支持时，应明确显示限制，并将差异提交用户审核，不能静默删除需求。

### 3.3 本期不做

账号、云同步、排行榜、付费、社交、运动课程、AI 对话、桌宠、养成、素材商店、浏览器扩展、手机端、复杂统计看板。

不默认根据鼠标键盘空闲自动认定已休息：阅读、思考和看视频时也可能久坐。此功能以后单独评估。

## 4. 用户主流程

```text
首次打开 → 小看板 → 确认间隔并点击“开始提醒”
    → 工作时段内后台计时 → 剩余 1 分钟时轻提醒 → 到期全屏“休息”
    → 休息倒计时结束 / 用户提前结束
    → 窗口收起 → 下一轮完整计时
```

后续正常启动是否自动开始，由保存的运行偏好决定；手动暂停状态另行保存，见第 7 节。

会议流程：

```text
检测到可信的会议信号 → 确认持续存在 → 暂停提醒并提示一次
    → 会议中保持暂停 → 确认会议结束
    → 若没有其他暂停原因，重新开始完整间隔并提示一次
```

## 5. 默认设置建议

| 设置 | 建议默认值 | 范围与说明 |
| --- | --- | --- |
| 提醒间隔 | 45 分钟 | 1–240 分钟，整数；预设 30 / 45 / 60，加自定义输入 |
| 休息时长 | 3 分钟（已确认） | 可自定义（已确认）；1–30 分钟整数、自动结束和允许提前结束仍为建议 |
| 休息前提醒 | 提前 1 分钟（已确认） | 建议默认开启，可关闭；静音轻提示，不提前全屏 |
| 工作时段 | 支持用户设置（已确认） | 默认是否启用、具体时段待审核；建议提供周一至周五 09:00–18:00 预设，可修改及添加午休间隔 |
| 铃声 | 关闭 | 开启后只在休息开始播放一次，不循环；结束保持静音 |
| 多屏 | 所有屏幕覆盖 | 每屏显示倒计时与结束按钮，同一轮同步结束 |
| 开机启动 | 关闭 | 用户主动开启，失败时显示实际状态 |
| 会议自动暂停 | 可选功能 | 首次说明后由用户开启；未验证的适配项不可伪装成已支持 |
| 会议暂停／恢复提示 | 静音 | 每次真实状态变化只提示一次，小看板持续显示状态 |
| 外观 | 跟随系统 | 支持浅色、深色，不依赖在线字体或资源 |
| 数据 | 仅本机 | 设置及有限休息记录，不上传 |

是否需要“稍后 5 分钟”列为待审核项，暂不作为基础闭环必做按钮。用户已明确可自行暂停，先避免增加第三种计时逻辑。

## 6. 界面规格建议

### 6.1 托盘／菜单栏

- 左键点击打开或收起小看板，靠近图标并限制在当前屏幕可视范围。
- 提供原生菜单：打开看板、暂停／恢复、现在休息、退出。
- 图标区分计时、手动暂停、自动暂停；状态不能仅靠颜色表达。
- 鼠标提示显示“距离休息 32 分钟”或具体暂停原因。
- Windows 默认不显示常驻任务栏窗口；Mac 默认不占 Dock。
- 图标被系统折叠时，再次启动应用能打开已有看板，不产生第二个计时器。

### 6.2 小看板

参考尺寸约 320 × 420 逻辑像素，不是不可调整的视觉定稿。

```text
┌────────────────────────────┐
│ Remind                  ⚙  │
│                            │
│       距离下次休息          │
│          32:18             │
│       每 45 分钟休息一次    │
│                            │
│ [ 暂停提醒 ] [ 现在休息 ]   │
│                            │
│ 提醒间隔          45 分钟  │
│ 休息时长           3 分钟  │
│ 提醒铃声             关闭  │
│                            │
│ ● 正在计时                 │
└────────────────────────────┘
```

自动暂停时显示“会议中 · 腾讯会议”及可展开的其他暂停原因。检测不确定时写“会议识别暂不可用”，不能写“当前没有会议”。

设置在同一个小窗口内切换或展开；休息前提醒开关、工作日与工作时段、开机启动、会议支持状态、版本、开源声明放在设置区。工作时段外，看板显示“非工作时段”，并显示下次工作时段开始时间；若同时手动暂停，也保留原因。表单未保存时不因失焦直接丢失编辑；普通状态面板失焦可收起。

### 6.3 全屏休息

- 柔和纯色背景，大字“休息”，次级文字“起来走一走，活动一下”。
- 显示剩余休息时间，结束按钮始终可见。
- Esc 提前结束；不要采用禁止退出、锁定输入的强制模式。
- 到期自动收起；不开大主页面，不要求用户回来确认。
- 多屏同步，任意屏幕结束会关闭本轮全部休息窗口。
- 全屏是覆盖当前屏幕的产品体验，底层可用无边框窗口实现，不要求进入系统全屏桌面。
- 不尝试覆盖系统登录、安全桌面等受保护界面；独占全屏程序的限制需实测并说明。
- 覆盖失败时用静音通知兜底，并显示故障状态；不能悄悄视为成功休息。

### 6.4 基本可用性

支持键盘操作、明确焦点、系统字体缩放、高对比度可读文字与减少动态效果。大字之外不使用快速闪烁或突然纯白高亮。全屏关闭后尽可能恢复原工作窗口，恢复失败不能阻碍退出。

## 7. 行为规则建议

### 7.1 计时与设置修改

- 以应用运行期间的可计时段为依据，不把“软件运行”表述成实际久坐测量。
- 手动暂停冻结当前剩余时间；手动恢复继续剩余时间。
- 会议结束、锁屏恢复、休眠恢复均要求下一次可计时时重新开始完整间隔。
- 如果自动暂停发生在手动暂停期间，也标记重置；用户以后手动恢复时开始完整间隔。
- 修改提醒间隔后，当前工作轮次重置到新间隔，小看板明确提示“下一次提醒已调整”；存在暂停时仍保持暂停。
- 修改休息时长只影响下一次休息，不改变已经展示的休息倒计时。
- 铃声关闭立即停止本轮正在播放的声音；开启不补播已经错过的铃声。
- 在休息中，“现在休息”不可重复触发；工作倒计时归零只产生一轮休息。

### 7.2 手动暂停

- 暂停持续到用户主动恢复，不设置隐蔽的自动恢复期限。
- 显示暂停原因及暂停开始时间，不反复通知用户恢复。
- 手动暂停偏好跨正常退出和重启保留；重启不恢复旧倒计时，恢复时开始完整间隔。
- 手动暂停时仍可点击“现在休息”，完成后仍保持手动暂停。
- 存在会议、锁屏或休眠暂停时，“现在休息”不可启动覆盖，说明当前原因；仅为非工作时段时仍可主动休息，完成后不开始时段外自动计时。
- 休息期间从托盘选择暂停：结束当前休息，记录为中断，再进入手动暂停。

### 7.3 自动暂停与组合

| 事件 | 计时与休息行为 | 用户反馈 |
| --- | --- | --- |
| 已确认会议开始 | 工作计时暂停；正在休息则立即收起并记为中断 | 静音提示一次，显示会议软件 |
| 已确认会议结束 | 仅清除该会议暂停原因；无其他原因时重新计满间隔 | 恢复则提示下次时间；仍手动暂停则说明仍暂停 |
| 锁屏或休眠 | 不计时；收起休息画面，中断本轮 | 不在锁屏上弹提示 |
| 解锁或唤醒 | 分别清除对应系统原因，核对实际锁屏状态；全部解除后重置间隔 | 更新看板，通常无需系统通知 |
| 用户手动暂停 + 会议结束 | 手动暂停继续有效 | 不误报“已恢复提醒” |
| 两场会议／两个会议软件 | 所有已确认会议都结束后才可解除会议暂停 | 看板可查看全部原因 |
| 用户关闭会议自动暂停 | 停止检测并清除会议原因，其他原因保留；无其他原因时重置间隔 | 明确更新状态 |
| 工作时段结束 | 停止工作计时与提前提醒；当前休息收起并记为中断 | 看板显示“非工作时段”，不弹下班通知 |
| 下个工作时段开始 | 仅清除时段原因；无其他原因时开始完整间隔 | 看板更新，不自动解除手动暂停 |

### 7.4 会议误判及失败

- “软件运行”“麦克风占用”“音量为零”都不能单独等同于会议真值。
- 要测试静音参会、只听不说、最小化、共享屏幕、入会预览、切换设备、断线重连。
- 飞书语音消息或语音输入不应被宣传为已可靠区分；无法区分时提示为实验性，默认不启用该适配项。
- 建议确认会议开始需信号持续 5 秒，结束需有效的结束证据持续 30 秒；这些参数等待实测校准。
- 检测异常不算会议结束。已在自动暂停时保持会议原因最多 2 分钟并重试；之后进入“会议状态待确认”暂停，提示用户手动继续或暂停，避免开会时因检测故障突然弹全屏。
- 故障前未处于会议中：保留原有计时，并在到期前再次检查；仍无法确认时，本次只用静音通知代替全屏，用户可恢复全屏提醒或手动暂停。明确显示本次降级，不标为正常全屏提醒。
- 设置内提供“本次忽略会议识别”：仅解除本次会议抑制，恢复手动控制；检测到有效结束后恢复该软件的自动识别。检测持续异常时可关闭功能，不长期保留隐形覆盖规则。
- 通知权限被拒绝或系统免打扰拦截时，不声称系统通知已送达；托盘与看板仍持续显示暂停／恢复状态。

### 7.5 启动、退出和异常

- 首次启动展示简短说明及默认值，点击“开始提醒”后运行，不在安装完成后突然全屏。
- 后续正常启动：上次未手动暂停则重新计满间隔；上次手动暂停则保留暂停。
- 退出不是暂停；退出后不提醒。再次启动不补发错过的休息。
- 应用异常重启后，不恢复旧全屏窗口；未结束的休息记录标为中断。
- 计时前先读取系统状态并获取会议首轮结果；会议检测超时按检测不可用规则处理。
- 修改电脑日期、时区不直接改变工作计时的经过时长；工作时段按新的本地时间重新判断，如因此跨越时段边界则按工作时段规则暂停／重置。
- 设置文件损坏时保留可恢复副本、提示已使用默认值；存储故障不使用户困在全屏里。

### 7.6 休息前 1 分钟提醒

提前量 1 分钟已确认；下列呈现和边界行为为建议。

- 剩余 60 秒时显示一次轻提示：“还有 1 分钟休息，可以准备收尾了。”不全屏、不抢焦点、没有铃声；小看板同步显示“即将休息”。
- 建议用短暂的屏幕角落浮层，不依赖用户已允许系统通知；具体展示时间在界面验证时确定。
- 轻提示不开始休息计时，也不推迟原定休息时间。仅开启休息铃声不会让提前提醒发声。
- 每轮最多提示一次；用户关闭提示不会取消到期休息。
- 暂停、开会、锁屏、休眠或进入非工作时段时，撤下当前提示并取消待发送提示；恢复时按新截止时间重新调度。
- 手动暂停后继续同一轮不重复提示；因会议／系统／工作时段重置形成新轮次后可以再次提示。
- 提醒间隔不超过 1 分钟时，建议跳过提前提醒，避免点击开始就被提醒；直接按用户设置的间隔休息。
- 手动“现在休息”不等待一分钟；回调延迟或应用卡顿跨过提前提醒点时，不补发已过时的提示。

### 7.7 工作日与工作时段

支持此功能已确认；下面的具体配置与恢复规则为建议，见 D15。

- 设置启用开关、每周工作日及一天内一个或多个时段，精确到分钟；例如周一至周五 09:00–12:00、13:00–18:00，可排除午休。
- 预设仅帮助填写，不认定用户固定朝九晚六。关闭时段限制时，恢复全天可计时模式。
- 初版建议所有选定工作日共用每日时段；可选星期六、日，不自动根据法定节假日调休。
- 时段按本机本地时间，以开始时刻包含、结束时刻不包含判断；空配置或重叠时段提示修正。
- 跨午夜时段初版建议提示拆分，不暗中调整所属工作日；如需要不同日期独立排班，再扩展设置结构。
- 工作时段开始只开放计时资格，不立即提醒；没有其他暂停原因才从完整间隔开始。
- 午休／下班后不累计、不补发提醒；应用在时段中途启动时也从完整间隔开始。
- 如果下一次休息会落在时段结束后，不为赶在下班前提前提醒；看板显示“本时段不再提醒”，下一时段重新计时。恰好落在结束时刻也不触发。
- 修改时段设置后立即重判；进入时段外则暂停并收起提示或休息画面，留在／进入可用时段则重置工作轮次，但保留手动和会议暂停。
- 只有时段限制这一项暂停时可“现在休息”；结束后仍为非工作时段。手动暂停不能被上下班边界自动清除。

## 8. 数据与隐私建议

- 不需要登录或云端服务；离线可完成核心提醒。
- 会议检测只使用必要的本地状态，不录音、不截屏、不读取会议内容或参会人。
- 如果特定适配方案需要系统权限，在用户开启时解释用途，拒绝后保留基础提醒。
- 休息记录只包含时间、计划时长、实际展示时长和结束类型，不存会议标题／窗口标题。
- 本期记录仅用于故障排查和以后数据兼容，不增加统计页面；建议最多保留 500 条且不超过 90 天。
- “完成休息”仅表示休息计时完成，不能解释为已确认运动。
- 不默认上传日志或自动收集遥测；提供用户主动清除本地记录的入口。

## 8.1 软件更新（新增已确认需求）

- 设置中展示当前版本和检查入口。默认不自动检查、下载或安装，不因退出应用自动安装。
- 检查到新版后由用户选择下载；显示进度，下载完成后由用户点击“重启安装”。安装动作明确告知将退出并重启应用。
- 休息、锁屏／休眠期间不安装，下载结果保留；安装过程暂停提醒，保留手动暂停意图。
- 检查／下载失败可以重试或手动下载，失败不能显示成“已是最新版本”。没有正式发布版本时明确提示。
- 只从固定发布源更新到经过校验的稳定版本。开发预览不冒充可升级的正式安装包。

## 9. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 默认设置开始计时，关闭看板 | 后台继续，45 分钟后出现一轮休息，默认无声 |
| A02 | 修改间隔为 1 分钟 | 明确显示重置后的剩余时间；正常运行下到期展示误差目标不超过 2 秒 |
| A03 | 暂停 10 分钟后恢复 | 剩余时间冻结并继续，不重复调度 |
| A04 | 手动暂停期间开会再结束 | 仍手动暂停，恢复后从完整间隔开始 |
| A05 | 支持的会议客户端开会、静音、最小化 | 在已测配置中保持暂停，结束稳定确认后恢复；记录支持版本 |
| A06 | 飞书只开着聊天、录一条语音消息 | 不因进程常驻永久暂停；语音误判必须在适配报告中暴露 |
| A07 | 电脑先锁屏再休眠，再唤醒但未解锁 | 保持系统暂停；解锁后重新计时，无立即全屏 |
| A08 | 双屏、三屏、不同缩放和负坐标屏幕 | 每屏正确覆盖，倒计时一致；任意屏结束全部收起 |
| A09 | 休息中插拔显示器或旋转屏幕 | 更新覆盖，无残留置顶窗口，无重复休息记录 |
| A10 | 休息中按 Esc／点结束／触发会议暂停 | 正确结束或中断，并区分记录类型 |
| A11 | 重复启动、连续点击操作 | 只有一个实例、一个计时核心和一轮休息 |
| A12 | 修改时钟、时区或进程短时卡顿 | 不提前／重复弹出；错过的多个周期不堆积补发 |
| A13 | 检测超时、权限拒绝、系统通知关闭 | 明确显示不可用／降级，按第 7.4 节处理，不伪装成正常识别 |
| A14 | 一个休息窗口加载失败 | 本轮不标记完成；通知兜底，保留退出手段和故障状态 |
| A15 | 重启应用、升级后读取旧设置 | 设置及手动暂停保留，旧记录可迁移；不开旧休息窗口 |
| A16 | 全程断网 | 核心提醒、设置和手动暂停可正常使用 |
| A17 | 开机启动开关与系统拒绝／禁用 | 显示系统实际状态；退出可彻底停止后台活动 |
| A18 | 自定义休息时长为 5 分钟并重启 | 设置保留；下一轮休息倒计时 5 分钟，当前已开始的休息不被更改 |
| A19 | 工作间隔 45 分钟，正常连续运行 | 第 44 分钟只轻提醒一次，第 45 分钟全屏休息；默认全程无声 |
| A20 | 提前提醒后手动暂停／进入会议／锁屏 | 提示及时收起，暂停期间无新提示；同一轮手动恢复不重复提示 |
| A21 | 工作间隔设为 1 分钟或手动现在休息 | 不在启动时发送无意义的提前提醒；手动休息立即开始 |
| A22 | 设置工作日及上午／下午时段 | 午休、下班、未选择日期不自动提醒；下一时段开始从完整间隔计时 |
| A23 | 手动暂停跨越工作时段结束与开始 | 始终保留手动暂停，不因上班时间到了自动恢复 |
| A24 | 截止时刻恰好为下班时刻，或更晚 | 不全屏、不提前发提示；显示本时段不再提醒 |
| A25 | 更改工作时段／本地时区、校正系统时间 | 重判当前工作资格，旧时段回调失效；没有重复或补发提醒 |
| A26 | 启动、发现新版、下载完成、普通退出 | 每一步都不擅自下载或安装，仅用户点击对应操作才推进 |
| A27 | 休息中安装、重复点击、断网或缺少发布版本 | 安装受阻但保留下载结果；不重复操作；显示真实失败及重试入口 |
| A28 | 已签名旧版安装后更新到更高版本 | 元数据、签名和架构正确，安装成功后设置及手动暂停保留 |

性能验收目标及测量口径见技术文档；这些是目标，不是已有测量结果。

| 编号 | 建议 | 为什么建议这样 | 可选调整 |

### 10.1 可考虑但建议延后的功能

| 建议 | 价值与取舍 | 当前推荐 |
| --- | --- | --- |
| 暂停 30 分钟／1 小时 | 避免忘记恢复，但会出现用户仍在忙时自动恢复的风险 | 保留长期手动暂停，定时暂停以后作为明确选项 |
| 跟随系统免打扰自动暂停 | 用户可能长期打开免打扰，结果整天没有休息提醒；系统通知也可能被拦截 | 首版不自动继承为暂停条件，设置说明全屏提醒与系统通知不同 |

另外，屏幕共享与演示场景要纳入会议测试。会议尚未确认的几秒内仍可能出现提醒，不能承诺绝对不会被共享出去；用户在重要演示前可手动暂停。这是自动识别延迟的实际限制。

## 11. 来自类似项目的产品提醒

- Stretchly 已积累多屏、自然休息、暂停与系统恢复规则，优先参考其已处理的边界；它的运行进程排除不等于实际会议识别。[源码依据](OPEN_SOURCE_RESEARCH.md#3-stretchly优先参考的基础实现)
- BreakTimer 有多屏及全屏相关公开问题，说明“有窗口 API”不能取代真实设备测试。[问题记录](https://github.com/tom-james-watson/breaktimer-app/issues/461)
- Mac 的腾讯会议检测已有麦克风元数据实现，但入会预览、静音、设备切换等仍须验证；不把麦克风占用直接当实际开会的绝对证明。[源码依据](OPEN_SOURCE_RESEARCH.md#4-会议识别调研)
- 提醒的价值依赖长期愿意保持开启，所以状态可见、能退出和默认静音优先于强制性；这是本项目的设计判断，不是上游已经替我们证明的结论。
